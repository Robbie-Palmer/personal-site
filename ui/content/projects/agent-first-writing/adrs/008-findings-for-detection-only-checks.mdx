# Context

[ADR 003](/projects/agent-first-writing/adrs/003-versioned-suggestion-contract)
requires every producer to return a replacement. That works for a correction
whose replacement is known. The repository's active Vale rules identify
passages that need rewriting but do not supply safe replacement text.

Encoding these alerts as deletions would produce broken sentences. Encoding
the source text as its own replacement would create no-op suggestions that a
consumer could mistakenly accept or apply. The rewrite belongs to a later
producer with enough context to make it.

# Decision

Keep the version 1 suggestion, proposal, and decision records from ADR 003. Add
a version 1 finding record for a producer that can locate a problem without
rewriting it.

A finding records:

* the producer ID, version, and rule or model provenance;
* the source document, revision, and SHA-256 hash;
* a half-open UTF-8 byte span and the exact source text it covers;
* a category and reason; and
* optional confidence.

Calculate its stable finding ID from the schema version, producer identity and
version, source identity and revision, source hash, span, and category. Keep the
reason, confidence, and detailed provenance outside the identity, as ADR 003
does for suggestions.

A finding has no replacement and does not form a proposal. Consumers must
verify its source hash and byte span before display or downstream processing.
A rewrite producer may consume findings and return suggestions under its own
version and provenance.

# Consequences

Vale can identify rewrite targets without claiming it knows the edit. A later
model stage gets stable inputs tied to exact source bytes and rules.

The editor now has two pre-review record types. Only suggestions form proposals
and receive accepted, rejected, or changed decisions. Evaluation must keep a
finding's detection result separate from the quality and outcome of a rewrite
that follows it.
