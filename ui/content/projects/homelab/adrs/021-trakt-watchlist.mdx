# Context

Adding media through Sonarr and Radarr's web UIs works, but the natural place
to decide what to watch next is a phone, on a couch, in a recommendations
feed — not an administration panel. A social tracking service turns "that
looked interesting" into a library entry: tap watchlist, the stack fetches
it. Watched-state should flow the other way too, so the tracker's
recommendations improve off what Jellyfin actually plays.

The family's taste lives on Letterboxd, which publishes no open API (its
partner program is closed), so it cannot be the automation source. Trakt is
the API-friendly alternative for both movies and shows.

# Decision

Two native integrations, each authorized once by hand:

* **Watched state**: the official [Jellyfin Trakt plugin][trakt-plugin]
  (pinned v30, which fixes a `MissingMethodException` under Jellyfin 10.11)
  is installed into the live config volume — and now by the Jellyfin
  bootstrap script itself, so fresh installs get it too. Authorizing it in
  the Jellyfin dashboard scrobbles every play to Trakt going forward.
* **Watchlist as acquisition queue**: Sonarr and Radarr each get a native
  **Trakt User** import list over the configured account's watchlist,
  authenticated through their own "Authenticate with Trakt" buttons. The
  lists bind to the TRaSH quality profiles from ADR 019 (`WEB-1080p` for
  TV, `HD Bluray + WEB` for movies), monitor everything they import, and
  search on add — so a watchlist tap enters the normal pipeline right away.
  Whether it ends in a grab still depends on release availability and the
  profile's scoring, exactly as for anything added by hand.

Because each integration authenticates as the user's own Trakt account, the
profile can stay private; nothing is read through anonymous endpoints.

[trakt-plugin]: https://github.com/jellyfin/jellyfin-plugin-trakt

# Alternatives

## Letterboxd bridge

* **Pros**: meets people where their taste already lives.
* **Cons**: no open API; only per-user RSS feeds, which carry diary entries
  rather than a curated forward-looking list. Would need scraping or feed
  parsing plus a custom add-to-Radarr bridge.
* **Decision**: Deferred until there is a concrete username worth bridging;
  Trakt covers the need now.

## Custom headless sync service

A small container doing Trakt's device-code OAuth itself, polling the
watchlist, and pushing adds into the \*arr APIs.

* **Pros**: zero manual steps beyond pasting one activation code; fully
  scriptable from provisioning.
* **Cons**: \~200 lines of token-refresh, diffing, and add-logic to maintain
  forever, duplicating what the \*arr import-list subsystem already does —
  including its edge cases around list removal and season monitoring.
* **Decision**: Rejected. The native path costs three one-time clicks and
  is maintained upstream.

## Import lists without OAuth

* **Decision**: Rejected. Radarr's validation refuses unauthenticated Trakt
  list configurations outright ("Must authenticate with Trakt"), even for
  public profiles where the underlying API call would have worked.

# Consequences

### Pros

* Phone → Trakt watchlist → monitored series/movie → grab → Jellyfin is
  fully wired with no custom code.
* The recommendation loop improves itself: Jellyfin plays scrobble to
  Trakt, Trakt recommends against real history.
* Upstream absorbs Trakt API changes; nothing here parses their payloads.

### Cons

* Three manual authorizations exist outside version control: the Jellyfin
  plugin user and one per \*arr app. A fresh bootstrap needs them redone —
  the click-paths live in the README caveats.
* List refresh runs on the scheduler at a minimum interval of 12 hours;
  same-day gratification means pressing "Refresh" on the Lists page.
* Removing something from the watchlist does not remove or unmonitor it in
  the \*arr apps; the queue drains forward only.
