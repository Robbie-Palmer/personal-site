# Context

Adding media through Sonarr and Radarr's web UIs works, but the natural place
to decide what to watch next is a phone, on a couch, in a recommendations
feed — not an administration panel. A social tracking service turns "that
looked interesting" into a library entry: tap watchlist, the stack fetches
it. Watched-state should flow the other way too, so the tracker's
recommendations improve off what Jellyfin actually plays.

The family's taste lives on Letterboxd, which publishes no open API (its
partner program is closed), so it cannot be the automation source. Trakt is
the API-friendly alternative for both movies and shows.

# Decision

One integration, one authorization, no native Trakt apps: a small bridge
script (`trakt_sync.py`) holds the account's **single** community-app
connection and drives the whole loop on an hourly schedule from the
keep-running agent:

* **Watchlist as acquisition queue**: the bridge polls the watchlist and
  adds shows to Sonarr (bound to `WEB-1080p`, `/media/TV`) and movies to
  Radarr (`HD Bluray + WEB`, `/media/Movies`) with monitoring and search
  enabled, so a tap enters the normal pipeline right away. Whether it ends
  in a grab still depends on release availability and profile scoring,
  exactly as for anything added by hand.
* **Watched state**: the bridge pushes Jellyfin's played episodes/movies to
  Trakt (`/sync/watched`), watermarking by play date so each pass sends only
  new activity — including a full-history backfill on first run.

Authorization uses Trakt's device-code flow against the user's own
registered application, so tokens live locally (0600) and never touch the
repo. Because the connection is the user's own token, the profile stays
private.

The turn away from native integrations came from a hard limit discovered
during setup: **free Trakt accounts may hold one community-app connection at
a time**, and the plugin-plus-two-import-lists design needs three slots.
Consolidating into one self-owned app makes the cap irrelevant.

# Alternatives

## Letterboxd bridge

* **Pros**: meets people where their taste already lives.
* **Cons**: no open API; only per-user RSS feeds, which carry diary entries
  rather than a curated forward-looking list. Would need scraping or feed
  parsing plus a custom add-to-Radarr bridge.
* **Decision**: Deferred until there is a concrete username worth bridging;
  Trakt covers the need now.

## Native integrations (Jellyfin plugin + \*arr import lists)

The first-cut design: the official Jellyfin Trakt plugin for scrobbling and
one OAuth'd "Trakt User" import list per \*arr app.

* **Pros**: zero custom code; upstream maintains every Trakt API change.
* **Cons**: three community-app connections, and free accounts allow one at
  a time — the second authorization attempt failed outright with "free
  accounts can connect one community app at a time". VIP (\~$5/mo) would
  lift the cap but rents a workaround for what is one small script here.
* **Decision**: Rejected after the cap surfaced live. The plugin install
  step remains in the Jellyfin bootstrap as an optional head start for
  anyone who later goes VIP.

## Import lists without OAuth

* **Decision**: Rejected. Radarr's validation refuses unauthenticated Trakt
  list configurations outright ("Must authenticate with Trakt"), even for
  public profiles where the underlying API call would have worked.

# Consequences

### Pros

* Phone → Trakt watchlist → monitored series/movie → search → Jellyfin is
  fully wired through a single connection that also carries watched-state,
  so recommendations improve off real viewing history.
* The free tier is sufficient forever; nothing about the loop depends on
  connection slots or subscription status.
* Tokens never leave the hub; the repo holds only configuration knobs.

### Cons

* \~200 lines of bridge code now track Trakt's API (watchlist shape, sync
  payloads, device flow) instead of upstream doing it.
* Watchlist changes propagate hourly, not on Trakt's native 12-hour list
  schedule; same-day picks still mean waiting up to the interval or running
  `trakt_sync.py sync` by hand.
* Removing something from the watchlist does not remove or unmonitor it in
  the \*arr apps; the queue drains forward only.
