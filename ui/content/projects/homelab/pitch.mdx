## Every solved problem leaves something the next one can reuse

1. Tailscale made the Mac mini reachable without a public service.
2. t3-code reused that host for four harnesses and their threads.
3. mise tasks, worktrees, a browser, and telemetry made changes easier to test.
4. The proposed phone lab can reuse the access, tasks, previews, and artifact collection.

<PitchStep>
  New work starts with access, commands, and feedback already working.
</PitchStep>

<PitchNotes>
  This is what cumulative value delivery means in this project. Each change solves its immediate problem and leaves a
  specific piece of infrastructure behind for later work.

## Cloud services stay where they earn their keep

<div className="pitch-value-ledger">
  <div><span>Keep</span><strong>Ente</strong><p>Encrypted cloud sync, plus plain-file backup in the lab</p></div>
  <div><span>Keep</span><strong>AI subscriptions</strong><p>Models stay; t3-code replaces their remote interfaces</p></div>
  <div><span>Keep</span><strong>Trakt</strong><p>Discovery and history, with Jellyfin for owned media</p></div>
  <div><span>Avoid</span><strong>New printer or NAS</strong><p>CUPS revives the printer; ordinary disks avoid appliance lock-in</p></div>
</div>

<p className="pitch-slide__statement">A better owned library may make some streaming subscriptions unnecessary.</p>

<PitchNotes>
  The streaming claim is deliberately tentative. Netflix, Disney Plus, Amazon Prime, and Apple TV remain subscribed
  today. The current gain is a quicker route from Trakt discovery to Jellyfin playback for content already owned. A
  Synology NAS would package storage, backup, sync, clients, and administration more neatly. The current lab accepts
  more assembly work because the Mac mini and disk already cover the immediate jobs.

  \[Sources]

  * [Ente export documentation](https://ente.com/help/photos/features/backup-and-sync/export)
  * [Ente photo backup ADR](/projects/homelab/adrs/007-ente-photo-backup)

# Reuse the pattern on hardware you already own

Use hardware you already own. Add private remote access, one agent interface, repeatable commands, and checks against
the running system.

<PitchStep>
  Fork the repo. Keep the decisions that solve a problem you actually have. Delete the rest.
</PitchStep>
